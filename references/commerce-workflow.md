# commerce-workflow — 证据驱动的带货素材工作流

> commerce 只处理用户上传的本地视频和商品材料。不抓在线商品页或平台视频，不找带货对标，不做选品与趋势监控。

## 1. 能力边界

| 输入 | 可以做 | 不可以做 |
|---|---|---|
| 本地带货视频 `.mp4/.mov` | 画面/口播/结构拆解、商品露出与风险审查 | 推断销量、GMV、商品点击率、成交率 |
| 详情页/SKU/价格/资质截图或文件 | 构建有来源的 ProductFactCard | 自动确认页面当前仍有效 |
| ProductFactCard + 账号定位/目标人群 | 生成 15s/30s/60s 口播、分镜、CTA | 使用未核验功效、价格、赠品或库存 |
| 用户导出的后台指标 JSON | 按指定账号历史样本归一化 | 自动登录后台、自动拉取投放数据 |

以下请求直接说明不支持，不生成替代结果：

- 只给商品链接并要求自动分析商品。
- 只给平台视频链接并要求自动下载或拆解。
- 自动找带货对标、选品 Top10、趋势雷达、佣金排行。
- 根据公开视频互动推断真实销量、GMV、点击率或转化率。

## 2. 路由

### commerce-review

输入：本地视频；商品名称。商品资料和后台指标可选。

1. 用 `scripts/analyze_video.py` 分析完整视频。
2. 输出视觉/文字/口播/剧情 4 维钩子。
3. 输出商品露出、利益点顺序、转化结构、商品卡一致性、复刻风险 5 维。
4. 只有提供商品资料时才判断商品卡一致性；否则明确写“未核验”。
5. 只有提供后台数据时才计算实际指标；否则不填估算值。

### commerce-adapt

输入：商品名称；至少一份商品证据；账号定位；目标人群。本地参考视频可选。

1. 逐份解析详情截图、SKU 表、资质文件和品牌资料。
2. 构建 ProductFactCard；每条事实记录文件名与页码/截图/行号。
3. 将材料未覆盖或互相冲突的字段放入 `pending_verification`。
4. 只用 `confidence=confirmed` 的事实生成口播和分镜。
5. 用 `scripts/build_commerce_package.py` 校验并生成 JSON；校验失败时不交付。

## 3. ProductFactCard 2.0

唯一契约定义在 `references/commerce-metrics.md`。Markdown 至少包含：

```markdown
# 商品事实卡

商品名称: 示例商品
商品链接: https://example.com/item/123  # 可选，仅记录
资料确认时间: 2026-08-13T00:00:00Z

## 商品事实
- 规格为 30ml，来源：sku.png 第 1 行
- 含透明质酸钠，来源：ingredient.pdf 第 2 页

## SKU
- 30ml/瓶 | 99.00 | 用户截图显示有货

## 待核验项
- 活动截止时间未提供
```

来源为空的事实不能进入确定性脚本。商品链接不是必填项，也不能替代证据。

## 4. 交付文件

```text
reports/
  commerce-review-{YYYYMMDD-HHMM}.md
  product-fact-{YYYYMMDD-HHMM}.md
  commerce-adapt-{YYYYMMDD-HHMM}.md
  commerce-package-{YYYYMMDD-HHMM}.json
```

没有完成事实卡或视频分析时不写半成品报告。

## 5. 错误处理

| 场景 | 处理 |
|---|---|
| 只有商品链接 | 要求上传详情页、SKU、价格活动和资质材料 |
| 只有平台视频链接 | 要求下载并上传本地视频文件 |
| 商品材料互相冲突 | 列出冲突，停止脚本生成 |
| 商品事实没有来源 | 放入待核验，不写入确定性口播 |
| 高风险品类缺资质 | 停止生成发布稿，只输出缺失资质清单 |
| 后台指标缺失 | 只做内容结构审查，不估算转化指标 |
